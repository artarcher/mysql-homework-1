Часть 1

Зачем нужны БД, СУБД и SQL

Шаг 1. Почему Excel не подходит для информационной системы колледжа?

Когда вы заходите в электронный дневник с телефона, вы видите своё расписание и оценки. Если вы потеряете телефон, оценки не исчезнут, потому что они лежат на сервере в Базе Данных.

Но почему учебной части просто не завести один большой файл Excel на компьютере директора и не вписывать туда все 2 000 студентов? Если хранить всё в одном файле, случатся три катастрофы:

  1. Зависание при одновременной работе: в конце пары 50 преподавателей одновременно ставят оценки, а 500 студентов смотрят дневник. Обычный файл зависнет или сотрёт чужие правки.
  2. Ошибки и отсутствие правил: кто-то напишет курс словом «первый», кто-то цифрой «1», а кто-то случайно нажмёт Delete и сотрёт целую группу.
  3. Медленный поиск: когда за 10 лет накопятся сотни тысяч оценок, поиск одного студента в обычной таблице займёт минуты.

Поэтому в IT используют связку из трёх вещей: БД, СУБД и SQL.

Тема: Основы баз данных и языка SQL

  1. БД (База Данных) — это цифровое хранилище (архив), где данные разложены по строгим таблицам.
  2. СУБД (Система управления базами данных) — программа-охранник и управляющий базой. Самая популярная СУБД — MySQL [Май-Эс-Кью-Эль].
  3. SQL [Эс-Кью-Эль] (Structured Query Language) — язык структурированных запросов, на котором мы отдаём команды программе MySQL.

Шаг 2. Устройство таблицы и зачем нужен столбец id

Внутри любой таблицы MySQL есть столбцы (поля) — это шапка таблицы, то есть характеристики (ФИО, группа, курс), и строки (записи) — это конкретные студенты. Одному студенту соответствует одна строка.

id full_name group_name course scholarship
1 Смирнов Алексей ИС-101 1 2500
2 Козлова Мария ДЗ-102 1 3500

Названия таблиц и столбцов всегда пишут латиницей и без пробелов. Если нужно два слова — ставим нижнее подчёркивание, например full_name [фул нЭйм].

Почему нельзя искать студента в базе просто по фамилии и имени? Потому что в колледже легко могут учиться два полных тёзки — два Ивановых Александра! Чтобы никогда не перепутать людей при начислении стипендии или отчислении, у каждой строки есть столбец id [ай-дИ] — уникальный номер в базе (как номер паспорта: 1, 2, 3...).

✍️ Записать в тетрадь (Конспект)

Устройство таблицы:

  • Столбцы (поля) — характеристики (пишутся латиницей без пробелов, через _).
  • Строки (записи) — конкретные объекты (один студент = одна строка).
  • id [ай-дИ] — уникальный номер строки в таблице (не может повторяться, нужен чтобы не путать однофамильцев).
Часть 2

Правило CRUD: Создание и чтение данных

Шаг 1. Правило CRUD и создание таблицы (CREATE TABLE)

Вся работа с данными в программировании строится на правиле четырёх букв — CRUD [крад]:

  • Create (Создание) — CREATE TABLE, INSERT INTO
  • Read (Чтение / Поиск) — SELECT
  • Update (Обновление / Изменение) — UPDATE
  • Delete (Удаление) — DELETE

Чтобы приказать MySQL построить новую таблицу студентов, мы пишем команду CREATE TABLE [криЭйт тЭйбл]. Обратите внимание на синтаксис:

  • Внутри круглых скобок через запятую перечисляются 5 наших столбцов. После каждого столбца стоит запятая, но после последнего столбца перед закрывающей скобкой запятая НЕ ставится! А в самом конце команды обязательно ставится точка с запятой ;.
  • Почему номер группы 'ИС-101' имеет текстовый тип VARCHAR, а не числовой INT? Потому что там есть буквы и дефис — для компьютера это текст!
✍️ Записать в тетрадь (Конспект + Код)
SQL — Создание таблицы
CREATE TABLE students (
    id INT PRIMARY KEY AUTO_INCREMENT,
    full_name VARCHAR(100) NOT NULL,
    group_name VARCHAR(20) NOT NULL,
    course INT DEFAULT 1,
    scholarship INT DEFAULT 0
);

Типы данных и параметры столбцов:

  • INT [инт] — целое число (1, 2500).
  • VARCHAR(100) [вАр-чар] — текст переменной длины до 100 символов (пишется в одинарных кавычках ' ').
  • PRIMARY KEY [прАймари ки] — первичный ключ (делает номер id уникальным и обязательным).
  • AUTO_INCREMENT [Ауто инкримЕнт] — автоматическая нумерация (+1 для каждой новой строки: 1, 2, 3...).
  • NOT NULL [нот нал] — запрет пустоты (поле обязательно нужно заполнить).
  • DEFAULT ... [дифОлт] — значение по умолчанию (подставится само, если поле не заполнили).

Шаг 2. Заполнение таблицы (INSERT INTO)

Таблица создана, но она пустая. Чтобы зачислить в неё студентов, используется команда INSERT INTO ... VALUES [инсЁрт Инту ... вЭльюс] — «Вставить в таблицу ... значения».

  • Почему мы не пишем в скобках столбец id? Потому что за него работает автомат AUTO_INCREMENT!
  • Главное правило кавычек: любой текст (VARCHAR) обязательно оборачивается в одинарные кавычки 'Смирнов Алексей', 'ИС-101'. А числа (INT) пишутся без кавычек.
✍️ Записать в тетрадь (Конспект + Код)
SQL — Добавление записей
-- Добавление строк в таблицу (INSERT INTO — вставить в..., VALUES — значения)
INSERT INTO students (full_name, group_name, course, scholarship) VALUES
('Смирнов Алексей', 'ИС-101', 1, 2500),
('Козлова Мария', 'ДЗ-102', 1, 3500);

-- Если не указать course и scholarship, сработает DEFAULT (курс = 1, стипендия = 0):
INSERT INTO students (full_name, group_name) 
VALUES ('Орлов Максим', 'ИС-101');

Шаг 3. Вывод на экран, фильтры и поиск (SELECT, WHERE, LIKE, ORDER BY)

За чтение данных и вывод ведомостей на экран отвечает команда SELECT [селЕкт] — «Выбрать / Показать»:

  • Звёздочка * означает «все столбцы».
  • Слово WHERE [вэа] («Где») включает фильтр. Условия можно связывать словами AND [энд] (И — оба условия сразу) или OR [ор] (ИЛИ — любое из двух).
  • Для поиска по кусочку слова (например, найти всех на фамилию «Смирн...») используется оператор LIKE [лайк] («Похоже на») и знак процента %, который заменяет любое количество любых символов.
  • Команда ORDER BY [Ордер бай] («Упорядочить по») сортирует таблицу: ASC [аск] — по возрастанию (от А до Я), DESC [дэск] — по убыванию (от максимума к минимуму), а LIMIT [лИмит] ограничивает количество выводимых строк.
✍️ Записать в тетрадь (Конспект + Код)
SQL — Выборка, фильтрация и сортировка
-- 1. Вывести ВСЕ столбцы (*) из таблицы
SELECT * FROM students;

-- 2. Вывести только нужные столбцы с точным фильтром WHERE (Где)
SELECT full_name, scholarship FROM students 
WHERE group_name = 'ИС-101' AND scholarship > 0;

-- 3. Умный поиск по части слова: LIKE и % (найдёт и Смирнова, и Смирнову)
SELECT * FROM students WHERE full_name LIKE 'Смирнов%';

-- 4. Сортировка ORDER BY (DESC — по убыванию, ASC — по возрастанию) и LIMIT
SELECT * FROM students ORDER BY scholarship DESC LIMIT 2;
Часть 3

Изменение, удаление и математика в БД

Шаг 1. Обновление (UPDATE) и удаление (DELETE FROM)

В жизни колледжа данные постоянно меняются: студент сдал сессию — ему нужно изменить стипендию с 0 на 3000. А кто-то окончил колледж — его нужно удалить из базы.

  • Для изменения существующей строки используется команда UPDATE ... SET ... WHERE [апдЭйт ... сет ... вэа].
  • Для удаления строки — команда DELETE FROM ... WHERE [дилИт фром ... вэа] (не забывайте предлог FROM!).
⚠️ Три главных правила безопасности (часто спрашивают на экзамене!):
  1. Почему в условии пишем WHERE id = 4, а не WHERE full_name = 'Орлов Максим'? Чтобы случайно не поменять стипендию или не отчислить его однофамильца!
  2. Что будет, если забыть написать WHERE в UPDATE или DELETE? MySQL мгновенно изменит или сотрёт вообще все строки в таблице, а кнопка Ctrl + Z в базах данных не работает!
  3. Куда деваются удалённые id? Если удалить студента с id = 3 (из 5 студентов), то следующему новому студенту AUTO_INCREMENT даст номер 6, а не 3. Удалённые номера повторно никогда не выдаются, чтобы на новичка не записались старые оценки или долги отчисленного студента.
✍️ Записать в тетрадь (Конспект + Код)
SQL — Изменение и удаление
-- Изменить данные (UPDATE — обновить, SET — установить новое значение)
UPDATE students 
SET scholarship = 3000, course = 2 
WHERE id = 4;

-- Удалить строку (DELETE FROM — удалить из...)
DELETE FROM students 
WHERE id = 3;

⚠️ Правило безопасности: Никогда не запускать UPDATE и DELETE FROM без условия WHERE id = ..., иначе изменятся или удалятся все записи в таблице! Удалённые номера id повторно не выдаются.

Шаг 2. Агрегатные функции (математика для бухгалтерии)

Чтобы считать статистику без калькулятора, в MySQL встроены 5 агрегатных (математических) функций. Важно не путать первые две: COUNT(*) считает количество строк (людей), а SUM(столбец) складывает числа внутри столбца (деньги или штуки).

✍️ Записать в тетрадь (Конспект + Код)

Агрегатные функции (статистика):

  • COUNT(*) [кАунт] — посчитать количество строк.
  • SUM(столбец) [сам] — посчитать сумму чисел в столбце.
  • AVG(столбец) [Эй-ви-джИ] — среднее арифметическое значение.
  • MIN(столбец) / MAX(столбец) — минимальное и максимальное число.
SQL — Подсчёт итогов
SELECT COUNT(*), SUM(scholarship), AVG(scholarship) FROM students;
Часть 4

Связи между таблицами (FOREIGN KEY, JOIN) и группировка (GROUP BY)

Шаг 1. Почему одной таблицы недостаточно? Внешний ключ (FOREIGN KEY)

Представьте: в группе ИС-101 учится 30 человек, и у всех один куратор — Белов Сергей Иванович. Если добавить столбец curator прямо в таблицу студентов, нам придётся 30 раз подряд скопировать его ФИО и телефон! Это занимает лишнюю память, приводит к опечаткам, а если куратор сменит телефон — придётся вручную менять его в 30 строках.

Программисты делят данные на две отдельные таблицы:

  1. Таблица groups_list [групс лист] (Список групп), где каждая группа и её куратор записаны ровно один раз под своим id (1 — ИС-101, 2 — ДЗ-102).
  2. Таблица students (Студенты), где вместо названия группы и ФИО куратора хранится просто цифра group_id [груп ай-дИ] — номер группы (1 или 2).

Базы со связанными таблицами называются реляционными (от англ. relation [рилЭйшн] — связь). Чтобы связать таблицы и защитить базу от ошибок (например, чтобы секретарь не мог зачислить студента в несуществующую группу №99), используется замок — внешний ключ FOREIGN KEY ... REFERENCES [фОрин ки ... рЭференсес].

✍️ Записать в тетрадь (Конспект + Код)

Реляционная БД — база данных, разделённая на несколько связанных по id таблиц, чтобы избегать дублирования текста и ошибок.

  • PRIMARY KEY [прАймари ки] — первичный ключ (собственный паспорт строки в своей таблице).
  • FOREIGN KEY [фОрин ки] — внешний ключ (столбец-ссылка, который указывает на id в соседней таблице).
SQL — Две связанные таблицы
-- 1. Главная таблица (Группы)
CREATE TABLE groups_list (
    id INT PRIMARY KEY AUTO_INCREMENT,
    group_name VARCHAR(20) NOT NULL,
    curator VARCHAR(100) NOT NULL
);

-- 2. Зависимая таблица (Студенты) со связью FOREIGN KEY
CREATE TABLE students (
    id INT PRIMARY KEY AUTO_INCREMENT,
    full_name VARCHAR(100) NOT NULL,
    scholarship INT DEFAULT 0,
    group_id INT,
    FOREIGN KEY (group_id) REFERENCES groups_list(id)
);

Шаг 2. Соединение таблиц на экране (JOIN ... ON)

Компьютеру удобно хранить в таблице студентов цифры 1, 2, 3 в столбце group_id. Но человеку в ведомости нужны понятные названия групп и фамилии кураторов. Чтобы прямо в момент вывода на экран временно «склеить» две таблицы в одну красивую ведомость, служит команда JOIN ... ON [джойн ... он]!

  • Когда в запросе участвуют две таблицы, названия столбцов пишут через точку: таблица.столбец (например, students.full_name, groups_list.group_name), чтобы MySQL точно знал, из какой таблицы брать данные.
  • После слова ON [он] («На основании») пишется правило сцепки: приравниваем внешний ключ студента (students.group_id) к первичному ключу группы (groups_list.id). Точка с запятой ; ставится только один раз в самом конце всего запроса!
✍️ Записать в тетрадь (Конспект + Код)
SQL — Соединение таблиц через JOIN
-- Склеиваем две таблицы при выводе на экран (JOIN — присоединить, ON — правило сцепки)
SELECT students.full_name, groups_list.group_name, groups_list.curator
FROM students
JOIN groups_list ON students.group_id = groups_list.id
WHERE students.scholarship > 0;

Шаг 3. Группировка данных (GROUP BY)

Функции COUNT(*) и SUM(scholarship) считают общее количество людей и сумму стипендий по всему колледжу. А что, если нужно узнать: «Сколько студентов учится в каждой группе по отдельности и сколько денег уходит на каждую группу?»

Для этого в конец запроса добавляют команду GROUP BY [груп бай] — «Сгруппировать по...». Она раскладывает строки в отдельные «корзинки» по номеру группы, и функции COUNT, SUM или AVG считают статистику внутри каждой корзинки отдельно!

✍️ Записать в тетрадь (Конспект + Код)
SQL — Группировка GROUP BY
-- GROUP BY [груп бай] — разбивает строки на категории и считает итоги для каждой отдельно
SELECT group_id, COUNT(*), SUM(scholarship)
FROM students
GROUP BY group_id;
Подготовка к зачёту

10 вопросов для самопроверки перед экзаменом

Попробуйте ответить на вопрос устно, а затем нажмите на него, чтобы проверить себя:

1. В чём разница между БД, СУБД и SQL?

БД — это сам архив с таблицами. СУБД (MySQL) — программа, которая управляет этим архивом и охраняет его от ошибок. SQL — язык команд, на котором мы пишем запросы для СУБД.

2. Какие два параметра мы пишем у столбца id, чтобы номера не повторялись и считались сами?

PRIMARY KEY (первичный ключ — обеспечивает уникальность и обязательность) и AUTO_INCREMENT (автоматическое увеличение номера на +1).

3. В чём разница между параметрами NOT NULL и DEFAULT?

NOT NULL строго требует заполнить поле при добавлении записи (иначе выдаст ошибку), а DEFAULT сам подставляет стандартное значение (например, 1 курс или 0 рублей), если поле оставили пустым.

4. Что случится с базой, если выполнить запрос: UPDATE students SET scholarship = 0; ?

Так как в запросе нет условия WHERE, абсолютно у всех студентов в таблице стипендия обнулится.

5. Если в таблице было 5 студентов и мы удалили студента с id = 3, какой id получит следующий новый студент?

Он получит id = 6. Параметр AUTO_INCREMENT никогда не выдаёт старые удалённые номера повторно.

6. Чем отличается поиск WHERE group_name = 'ИС' от WHERE group_name LIKE 'ИС%'?

Знак = ищет только точное совпадение из двух букв 'ИС', а LIKE 'ИС%' благодаря джокеру % найдёт все группы, которые начинаются на ИС (ИС-101, ИС-202 и т.д.).

7. Чем отличается функция COUNT(*) от SUM(scholarship)?

COUNT(*) считает количество строк (сколько человек в списке), а SUM(scholarship) складывает сами числа внутри столбца (общую сумму денег).

8. Чем отличается PRIMARY KEY от FOREIGN KEY?

PRIMARY KEY (первичный ключ) — это личный уникальный номер строки в её собственной таблице, а FOREIGN KEY (внешний ключ) — это столбец-ссылка, который указывает на id в соседней таблице.

9. Какая команда склеивает две таблицы при выводе на экран и какое слово задаёт правило их сцепки?

Команда JOIN (присоединить), а правило сцепки ключей пишется после слова ON (например, ON students.group_id = groups_list.id).

10. Зачем в конце запроса пишут команду GROUP BY?

Чтобы разбить строки на категории (например, по группам или предметам) и посчитать статистику (COUNT, SUM, AVG) для каждой категории по отдельности.
