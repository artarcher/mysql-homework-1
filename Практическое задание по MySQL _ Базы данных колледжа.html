Комплексное домашнее задание по MySQL

Информационная система колледжа | Курс «Базы данных и СУБД» (1 курс)

Темы 1, 2 и 3 Срок сдачи: к следующему занятию Очная индивидуальная защита

1. Зачем нужно это задание?

В реальной разработке база данных — это основа любого сайта, мобильного приложения и корпоративной системы. За первые три занятия мы прошли полный базовый цикл работы с данными (CRUD), агрегацию и проектирование связанных таблиц.

Цель задания — самостоятельно спроектировать модуль «Учебный деканат колледжа» из двух связанных таблиц, наполнить его данными, выполнить управление записями и сформировать сводные отчёты.

2. Техническое задание (Что нужно написать)

Работу необходимо выполнять в едином SQL-файле (например, homework.sql) либо в онлайн-песочнице OneCompiler (MySQL) / SQLiteOnline (MariaDB).

Часть А. Проектирование двух таблиц со связью

Спроектируйте две таблицы:

  1. Таблица отделений колледжа departments:
    • id — целое число, первичный ключ (PRIMARY KEY), автонумерация (AUTO_INCREMENT).
    • department_name — название отделения (текст до 100 символов, обязательное поле NOT NULL, например: «Информационные технологии», «Дизайн», «Экономика»).
    • head_of_department — ФИО заведующего отделением (текст до 100 символов, обязательное поле).
  2. Таблица учебных групп college_groups:
    • id — целое число, первичный ключ, автонумерация.
    • group_code — шифр группы (текст до 20 символов, обязательное поле, например: «ИС-101», «ДЗ-102»).
    • students_count — число студентов в группе (целое число, по умолчанию 0).
    • course_num — номер курса (целое число, по умолчанию 1).
    • department_id — внешний ключ (FOREIGN KEY), связывающий группу с её отделением из таблицы departments(id).

Часть Б. Наполнение данными (INSERT INTO)

  1. Добавьте в таблицу departments 3 разных отделения.
  2. Добавьте в таблицу college_groups минимум 5 учебных групп, распределив их по разным отделениям через номер department_id (1, 2 или 3).

Часть В. Модификация и удаление (UPDATE, DELETE)

  1. Перевод на следующий курс: Увеличьте номер курса (course_num) на 1 у конкретной группы по её id.
  2. Корректировка состава: Измените количество студентов (students_count) в одной из групп на новое значение. Обязательно используйте фильтрацию WHERE id = ....
  3. Расформирование группы: Удалите одну группу из таблицы college_groups по её id с помощью команды DELETE FROM.

Часть Г. Выборки, отчёты и связывание (SELECT, LIKE, JOIN, GROUP BY)

Напишите 4 отдельных аналитических запроса:

  1. Поиск по шаблону: Найти все группы, чей шифр начинается на буквы 'ИС%' с помощью оператора LIKE.
  2. Сводная ведомость деканата (JOIN): Вывести список всех групп с указанием шифра группы, курса, названия отделения и ФИО заведующего отделением. Цифр id в результате быть не должно — только понятные человеку названия.
  3. Сортировка: Вывести список всех групп, отсортированный по количеству студентов от самой многочисленной к самой малой (ORDER BY ... DESC).
  4. Статистика по отделениям (GROUP BY): Сгруппировать группы по отделениям (department_id) и посчитать:
    • Сколько всего групп на каждом отделении (COUNT(*)).
    • Сколько суммарно студентов учится на каждом отделении (SUM(students_count)).

3. Что вы обязаны знать и понимать (Теоретический минимум)

На защите преподаватель не оценивает слепо скопированный код. Вы должны уметь объяснить своими словами:

  • Чем отличается PRIMARY KEY от FOREIGN KEY.
  • Зачем нужен параметр AUTO_INCREMENT и почему база не переиспользует номера удалённых строк.
  • Почему выполнение UPDATE или DELETE без условия WHERE является критической ошибкой.
  • Что делает символ % внутри оператора LIKE.
  • Как работает склейка JOIN ... ON и зачем перед названием столбца ставить имя таблицы через точку (например, college_groups.group_code).
  • Чем функция COUNT() отличается от функции SUM().

4. Регламент и правила очной защиты

Формат сдачи: Защита проходит очно, индивидуально, за компьютером преподавателя или аудитории на следующей паре.
  1. Предъявление SQL-кода: Вы открываете свой готовый файл или онлайн-песочницу, запускаете скрипт и демонстрируете результат выполнения всех команд без синтаксических ошибок.
  2. Контрольный вопрос по коду: Преподаватель указывает на случайную строку в вашем запросе (например, ON ... = ... или DEFAULT 1) и просит объяснить назначение каждого слова.
  3. «Живая правка» (Live Coding): Преподаватель даёт одно маленькое дополнительное условие на 1 минуту прямо во время сдачи (например: «А теперь измени запрос так, чтобы выводились только группы 2-го курса» или «Посчитай среднее число студентов через AVG»).
Важно для тех, кто пропустил лекцию:
Если вы отсутствовали на занятии, оценка за тему №3 не может быть выставлена «автоматом». Успешная очная защита данного домашнего задания является обязательным допуском к закрытию пропущенной темы и промежуточной аттестации.

5. Критерии оценивания

Оценка Критерии
«Отлично» (5) Скрипт полностью рабочий, без ошибок. Созданы обе таблицы с корректным внешним ключом. Написаны все запросы (включая JOIN и GROUP BY). Студент уверенно отвечает на вопросы и справляется с «живой правкой».
«Хорошо» (4) Скрипт выполнен, но есть мелкие недочёты в синтаксисе, либо студент путается в разнице между COUNT и SUM / долго вспоминает конструкцию JOIN.
«Удовлетворительно» (3) Выполнена только первая половина задания (создание и вставка), но связь таблиц и агрегатные функции не работают или написаны с чужой помощью без понимания логики.
«Не зачтено» (2) Задание не выполнено к началу пары, либо код сгенерирован/списан, и студент не может объяснить значение собственных строк. Назначается повторная сдача.
